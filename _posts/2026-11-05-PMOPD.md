## 0. Abstract

MOPD(Multi-teacher on-policy distillation) 가 언어모델에 특화된 능력을 통합 하는 방법으로 떠오르고 있음.

MOPD는 공유 파라미터 내에서 여러 능력 통합해야하고 하나의 도메인 개선이 다른 도메인에서 얻은 능력 억제하는 **capability seesaw** 현상을 해결해야됨.

MOPD 과정 중 서로 다른 작업의 파라미터 업데이트가 각자의 **low-dimensional subspace** 빠르게 집중된다는 점 발견

Gradient와 Optimizer 업데이트 모두 투영해 task 방향 방해하는 구성요소 제거하는 **PMOPD(Projection-based Multi-Teacher On-Policy Distillation)** 제안


## 1. Introduction

Base Model에서 수학, 추론, 코드와 같은 도메인별로 별도의 Teacher 모델 학습하고 이를 Student Model에 증류 하는것이 MOPD

MOPD는 여러 teacher모델이 동일한 student 파라미터에 작용하게 되며, 이는 한가지 능력을 향상시키면 다른 능력이 억제되는 **capability seesaw** 현상 생길 수도 있음

본 논문은 OPD의 업데이트 기하학적인 부분에 접근

Task 별 누적 update가 안정적인 저차원 subspace를 형성함을 확인

Gradient와 Optimizer update에 double projection을 적용해 간섭을 완화함

Qwen, Llama에서 기존 벤치마크보다 모든 테스크에서 성능 향상했음



## 2. PROBLEM FORMULATION AND GEOMETRIC MOTIVATION

#### 1. Multi task Objective function
 여러 task의 OPD Loss 식은 다음과 같음

$$
\
\min_{\theta} \mathbb{E}_{t \sim q, x \sim D_t, y \sim \pi_{\theta}} \left[ \mathcal{L}_{\text{OPD}}^t(\theta; x, y) \right],
\
$$
   - Task scheule q 에 따라 task 선택
   - 해당 task의 prompt에서 student가 생성한 trajectory를 teacher모델이 평가

#### 2. Task-Update Subspaces
   1. 하나의 task block 동안 누적된 파라미터 업데이트

$$
\
\Delta W^t = W^{\text{after}} - W^{\text{before}}
\
$$
 - 하나의 task block이 끝나고 난 뒤에 파라미터 변화량

  2. SVD
    - 파라미터 변화량을 주요방향과 크기로 분해

$$
∆W^t = U_tΣ_t(V_t)^⊤
$$
  - 변화량 행령을 변화가 두드러진 K개의 방향 선택
  - K=16 이라면 누적 가중치 행령에 대해 상위 16개 Right Singular Vector 보관


 3. Subspace 유사도 Score

$$ 
\
\boxed{
S_K(a,b)=\frac{1}{K}
\left\|V_K(a)^\top V_K(b)\right\|_F^2
}
\
$$

2. REVERSE-KL ON-POLICY DISTILLATION

$$ 
\
\text{KL}(\pi_{\theta} \| \pi_{T}^{t}) = \sum_{v \in \mathcal{V}} \pi_{\theta}(v \mid h_i) \log \frac{\pi_{\theta}(v \mid h_i)}{\pi_{T}^{t}(v \mid h_i)}.
\
$$ 

간단하게 말하면 task에서 뽑은 프롬프트 x를 student가 먼저 생성하고 동일한 Prefix에서 teacher모델이 생성한 확률 분포와의 차이가 최소가 되게하는 목적함수이다

#### 3. Gradient Projection (1차 Projection)

$$
G_{\perp} = G - GMM^\top
$$

- $G$: Backpropagation으로 계산된 Gradient
- $M$: 이전 Task의 주요 Update 방향을 저장한 Subspace Memory
- $GMM^\top$: Gradient 중 보호 Subspace와 겹치는 성분
- $G_{\perp}$: 겹치는 성분을 제거한 Gradient

**목적:** 새로운 Task 학습 시 이전 Task의 주요 Update 방향을 보호한다.

#### 4. Optimizer Update Projection (2차 Projection)

$$
U_{\perp} = U - UMM^\top
$$

$$
W \leftarrow W - U_{\perp}
$$

- $U$: Adafactor의 Adaptive Preconditioning을 거친 Optimizer Update
- $UMM^\top$: Optimizer Update 중 보호 Subspace와 겹치는 성분
- $U_{\perp}$: 겹치는 성분을 제거한 최종 Update
- $W$: Student의 Weight Matrix

**목적:** Adafactor가 Gradient의 방향을 변경하면서 보호 Subspace와의 중첩이 다시 발생할 수 있으므로, 실제 Weight Update 직전에 한 번 더 Projection을 수행한다.

### 핵심 차이

| 구분 | 1차 Projection | 2차 Projection |
|---|---|---|
| 대상 | Gradient $G$ | Optimizer Update $U$ |
| 적용 시점 | Backpropagation 이후, Gradient Clipping 이전 | Adafactor Preconditioning 이후, Weight Update 이전 |
| 목적 | Gradient의 보호 방향 제거 | 실제 Parameter Update의 보호 방향 제거 |

**핵심:** PMOPD는 Gradient와 실제 Optimizer Update에 각각 Projection을 적용하는 Double Projection으로 이전 Task의 주요 Update Subspace를 보호한다.
